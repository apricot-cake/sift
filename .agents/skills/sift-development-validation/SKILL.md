# Sift の開発版を検証する

検証を始める前に、リポジトリの `docs/development.md` を読む。このスキルへ手順を複製せず、同ファイルを正本として扱う。

変更に応じた自動検査を通した後、次を満たす。

1. `npm run dev` を起動または再利用し、検証中は終了させない。起動メッセージだけでは成功とみなさない。
2. `npm run dev:browser` で開発用プロファイルを開く。検証ツールは `http://127.0.0.1:9222` の CDP へ直接接続する。日常用 Chrome や ChatGPT のブラウザ操作用拡張機能は使わない。
3. 開発サーバーの起動後に記録された接続ログで、開発版の接続と content script の登録が完了したことを確認する。過去のログを現在の成功根拠にしない。
4. 変更した経路を開発用プロファイルで実際に操作する。見た目を変更した場合は、対象画面が表示され、操作後の状態も崩れていないことを確認する。

X または Misskey のフォロー中タイムラインが変更対象に含まれる場合は、開発用プロファイルにある実投稿を使って正方向の動作も確認する。検証用アカウントは X で NHK PR、Misskey で現在気温ボットをフォローしている。

開発サーバーが終了した場合、サイドパネルが白い場合、または接続が完了していない場合は検証未完了とする。まず開発サーバーの稼働と現在の接続ログを確認し、それから実装の例外を調べる。

自分で実機操作を確認できない場合は、確認できた範囲とユーザーが確認する項目を明示する。実機操作を確認したとは言わない。

自動検査、現在の接続、変更経路の実機操作がすべて成功してから完了を報告する。
