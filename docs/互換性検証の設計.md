# 互換性検証

## 完了条件

- CIでは保存済みHTMLから情報取得・ページ判定・絞り込みを検証する。
- 実サイトでは並び順、投稿カード、指標、投稿日など依存部分の構造を保存した基準と比較する。本文、指標値、投稿ID、広告を基準に含めない。
- 固定URLだけでなくサイト内リンクによる遷移先も確認する。期待するページ・並び順・操作欄はSiftの判定結果から生成しない。
- 実サイトのE2Eでは閉じたパネルを起動し、実投稿で各フィルターの適用・解除を確認する。接続・アクセス権の確認も実行する。
- 実行時は対象外、読み込み中、投稿なし、アクセス権なし、必要情報の取得失敗を区別する。一部の投稿の欠損も診断に残す。
- ビルド、自動テスト、開発用Chromeでの検証、同一成果物の日常版への配備の順を守る。検証中に日常版の成果物を上書きしない。
- 定期実行は設けない。未確認・環境不備・構造差分を自動的に合格へ変換しない。

## 判定と記録

各ページでは、各フィルターの操作・解除と、条件に合う投稿を誤って隠さないことを確認する。除外対象がない場合は「操作確認のみ」と記録し、効果確認済みには数えない。除外効果はサイト・フィルターごとに少なくとも一つの代表ページで実投稿を使って確認する。別サイトの成功では代用しない。操作・解除の未確認ページ、または代表ページで効果未確認の項目が残る場合は配備しない。

構造差分があり動作が成立する場合は要確認とする。必要情報や操作の失敗は不合格とする。ログイン切れ・通信失敗は検証未完了として区別する。基準の更新は明示的な操作とし、通常の検証では上書きしない。

取得失敗は読み込み直後には断定せず、猶予時間内に復旧するか確認する。空一覧はサイト自身の空表示で確定し、カードが取得できなかっただけでは0件と断定しない。構造の変更を検知しても、その原因がサイト変更か通信・読み込みの異常かは断定しない。

検証結果にはビルドID・成果物ハッシュ・検証対象・実測結果・基準との差分を残す。配備は検証済み成果物と一致する場合だけ許可する。検証後の再ビルドは別成果物として再検証する。

ビルドIDは実際に開いたパネルから、稼働中のバックグラウンドへ問い合わせて照合する。拡張機能のファイルを再取得しただけでは、古いコードが実行中でないことを証明できないため、稼働確認の代用にしない。この応答はローカル配備ビルドのサイドパネルからの要求に限定する。

対応ページから対象外へ移動した際の解除、対応ページへ戻った際の復旧、パネル再起動時の最低値初期化も、フィルター単体とは別ケースとして記録し、配備条件に含める。

空一覧も独立したケースとして配備条件に含める。`empty-x-search` はサイトの検索結果なし表示を確認したうえで、パネルの投稿なし表示、操作欄がないこと、非表示状態が残らないことを検証する。通常の投稿一覧でのフィルター検証を、この結果で代用しない。

X のプロフィールはポストだけを対応ケースとし、返信・動画・画像を対象外ケースとして検証する。Bluesky は投稿・メディア・ビデオを対応ケースとし、返信を対象外ケースとして検証する。サイト内のタブ・メニューから切り替え、選択状態を確認してからパネルの案内を照合する。

`unsupported-*` は対象外のページ・並び順で閉じたパネルから起動する。対象外の案内、操作欄がないこと、フィルターが無効で非表示状態もないことを確認する。YouTubeの古い順はプルダウン型とチップ型を別ケースとし、表示形式自体も照合する。

代表ページに現れないA/Bテストや未知のURL変更は網羅を保証できない。異常を発見した表示形式は、個人情報を除いたfixtureと検証ケースに追加する。

## 実行コマンド

`npm run build:candidate` で検証用成果物を作り、`npm run browser:candidate` で開発用Chromeへ読み込む。日常版の共有出力は変更しない。

`npm run test:live -- --grep <ケース名>` は部分的な再確認に使う。基準の初回登録・更新は `npm run test:live -- --update-snapshots` で明示的に実行し、差分を確認する。通常の実行では基準が存在しない場合も不合格になる。

全検証は `npm run verify:candidate` で実行する。自動テスト、実サイトE2E、アクセス権喪失・再接続の検証がすべて成功した場合だけ合格記録を発行する。基準を更新した場合も、候補をビルドし直して通常の比較を通す。

静的検証が通った後は、実サイトE2Eが失敗しても接続確認まで実行する。どちらかの失敗、事前確認の不一致、結果照合の失敗は不合格として終了時刻と理由を残し、合格記録を発行しない。

`npm run deploy:local` はソースと成果物のハッシュを合格記録と照合し、同一のバイト列を共有出力へコピーする。再ビルドはしない。旧成果物は `.output/promote-*/previous` に退避する。

実行対象は `e2e/cases.ts`、通常ページのフィルター項目は `requiredFilterEvidence` で管理する。手順書の20状態・78項目に、YouTubeの表示形式、除外効果の代表ページ、空一覧、対象外、遷移を追加している。起動ケース数とフィルター項目数は別に数え、部分実行の成功を全検証の成功として扱わない。

## 根拠

ユーザーに見える動作を検証し、役割・ラベルを優先して操作対象を指定する方針は [PlaywrightのBest Practices](https://playwright.dev/docs/best-practices) に沿う。構造比較はこの動作検証を補う証拠として扱う。

実機の操作範囲と合否基準は [実機検証](実機検証.md) を参照する。
