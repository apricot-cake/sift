# Chrome ウェブストアへの提出

最終更新日: 2026年10月31日

## 掲載内容と提出物

sift は、X・Blueskyでイラストを探すためのSNSイラストフィルターです。いいね数、画像・動画の有無、返信・引用・リポストの除外で、画面から読み取った投稿をサイドパネルに表示し、パネル内の一覧を絞り込みます。元ページの投稿は非表示にしません。画像の内容からイラストかどうかを自動判定する機能はありません。

対応する画面は [対応サービス](対応サービス.md)、日本語・英語の掲載文と権限理由は [掲載情報](../store-assets/listing.md) をご覧ください。

掲載内容、提出パッケージ、公開版の状態は、それぞれ確認します。提出前に、生成した ZIP と掲載内容、権限理由、データ利用申告を照合してください。

## 提出前の確認項目

| 項目 | 確認内容 |
| --- | --- |
| 対応範囲 | X・Blueskyの対応する一覧ページだけから投稿を読み取り、元ページの表示を変更しない |
| 掲載文 | 用途・主要機能・使い方を説明し、対応サービスと掲載情報の確認事項に照らして正確さを確認する |
| 掲載画像 | 現行の用途・対応範囲を示す画像を使う。[画像資料](../store-assets/screenshots/README.md)を確認する |
| マニフェスト | MV3、権限は storage・activeTab・scripting・sidePanel。署名用 key とローカル配備専用 nativeMessaging を含めない |
| バージョン | 提出版が公開版より新しいことをダッシュボードで確認する |
| データ利用 | ウェブサイトのコンテンツと接続先 URL の扱いを申告し、[プライバシーポリシー](../PRIVACY.md)と照合する |
| 実機検証 | [実機検証](agents/実機検証.md)の対象マトリクスと再接続確認に合格する |
| ZIP | ファイル一覧、マニフェスト、ロケール、不要ファイルの除外を提出物で確認する |

## 権限とデータ利用

- `storage`: サイト別の絞り込み条件を Chrome の同期ストレージに保存します。接続先タブの URL・識別子、元の一覧・選択タブの情報、画像拡大中のページ移動を判定するための URL と時刻は、セッション中だけ保存します。接続情報は同期しません。
- `activeTab`: ユーザーがツールバーのアイコンを押したタブへの、一時的なアクセスに使います。
- `scripting`: ユーザーが起動した対応サイトのタブへ、パッケージ内の投稿読取処理と、パネル開閉時の閲覧位置を保つ処理を実行します。
- `sidePanel`: 閲覧中のページと並べて、収集した投稿、絞り込み条件、接続状態を表示します。

投稿URL、投稿者、本文、画像URL、指標、メディア種別、返信・引用・リポストの区分をブラウザー内で読み取り、同じ一覧内で最大1,000件を一時保持します。投稿は永続保存しません。接続先 URL の参照・セッション保存と、閲覧履歴の蓄積や外部送信は区別します。絞り込み条件は、Chrome の同期が有効な場合に Google の同期機能で端末外へ送られます。

[ユーザーデータの公式 FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)と[申告欄の公式説明](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy/)に沿って、提出時点の実装と申告欄を確認してください。

公開済みの旧ビルドを利用するユーザーが残る間は、プライバシーポリシーの旧ビルドに関する説明を維持します。更新版の公開後に、実際の公開状態と照合して見直してください。

## 提出フロー

ZIP のアップロード、審査提出、状態確認は公式 API v2 を基本とします。API に対応していない説明文、掲載画像、権限理由、データ利用申告などの確認・更新だけ、Codex の内蔵ブラウザで開発者ダッシュボードを操作します。[API の対応範囲](https://developer.chrome.com/docs/webstore/api/reference/rest)

| 作業 | 使用する方法 |
| --- | --- |
| 検証・ストア用 ZIP 作成 | ローカルまたは GitHub Actions |
| ZIP アップロード・審査提出・状態確認 | 公式 API v2 |
| 説明文・掲載画像・権限理由・データ利用申告の確認と更新 | 内蔵ブラウザ |

1. 提出対象の修正を終え、対象バージョンの ZIP を生成・検証してください。
2. 内蔵ブラウザーで掲載内容を確認し、必要な変更を下書きとして保存してください。ZIP 更新後に権限の申告欄が変わった場合は、審査提出前に照合し直してください。
3. ZIP 更新で権限の申告欄が変わる場合は、手動実行の `upload_only` でアップロードだけを行ってください。その後、内蔵ブラウザーで新しい権限理由を照合・保存してください。
4. 審査へ提出する場合は、通常モードで ZIP のアップロードと審査提出を実行してください。掲載内容の編集、下書き保存、`upload_only` だけでは審査へ提出されません。
5. API で提出状態を確認してください。通常モードでは、審査承認後に自動公開します。
6. 審査提出を確認したら、次節の手順で GitHub Release にリリースノートを公開してください。

GitHub Actions の「Chrome ウェブストア提出」は、検証、ストア用 ZIP 作成、API によるアップロードと審査提出をまとめて行います。実行前に掲載内容の下書き保存を済ませてください。通常の main push では提出しません。

手動実行で main を選択し、提出するバージョンを入力します。GitHub Release は提出内容の記録に使い、公開してもストア提出は始まりません。

初期設定後の接続確認では、手動実行の `check_only` を有効にし、現在の `package.json` のバージョンを入力します。検証と ZIP 作成後に認証し、ストアの状態を読み取ります。アップロードや審査提出は行わないため、公開済みと同じバージョンでも確認できます。

権限の申告欄を更新するための `upload_only` は、アップロードの成功まで確認して停止します。`check_only` とは併用できません。申告の保存後は同じコミットを通常モードで実行し、生成した ZIP を再アップロードして審査へ提出します。`upload_only` のジョブ成功は、審査提出を意味しません。

提出前に、この文書の「提出前の確認項目」「権限とデータ利用」と開発者ダッシュボードの説明・権限理由・データ利用申告を内蔵ブラウザで照合してください。掲載文の案は [掲載情報](../store-assets/listing.md) を使います。API ではこれらの登録内容を取得・更新できません。内蔵ブラウザで本人確認が必要な場合は、ユーザーがログインしてから続けます。実機確認は [実機検証](agents/実機検証.md) に従って行います。GitHub 上の検証だけでは実機確認を代用しません。

検証済みの ZIP は、Actions の成果物（artifact）として14日間保存します。提出には同じ ZIP を使います。アップロード失敗、審査中、公開待ち、公開版以下のバージョンでは処理を停止します。提出 API の応答が不明になった場合は、API の状態確認を先に行い、確認できなければ内蔵ブラウザで状態を確認してから再実行してください。

提出モードでのジョブ成功は審査提出の成功を意味します。審査承認や公開完了の確認とは別です。状態は API で確認し、審査理由など API で得られない詳細は内蔵ブラウザで確認します。

## リリースノート

ストア提出ごとに GitHub Release へ変更点を記録します。

1. 提出前に `store-assets/release-notes/<バージョン>.md` を用意します。前回の提出からの主な変更点を短く書きます。
2. 審査提出を確認したら、提出日と実行記録へのリンクを原稿へ追記します。提出とストア公開は区別します。
3. 実際に提出したコミットへ `v<バージョン>` タグを付け、原稿を GitHub Release に公開します。

掲載文・画像だけの更新は、同じ版の原稿と Release に日付付きで追記します。タグは動かしません。

通常提出と `upload_only` は原稿がない場合に停止します。`check_only` は原稿なしで実行できます。

過去の記録は、提出元と日付を確認できたものだけ作成します。古いタグに自動提出の設定が残っている場合は、Release の公開中だけ提出ワークフローを停止し、完了後に元へ戻します。

## GitHub Environment

Environment（提出用の変数と権限をまとめる GitHub の設定）の名前は `chrome-web-store` です。許可するブランチは main です。必須承認者と待機時間は設定しません。提出できるコミットとバージョンはワークフローでも検査します。

`deployment: false` で Deployment の作成を止め、実行結果は Actions に記録します。

次の Environment variables（環境変数）を設定してください。これらは秘密情報ではありません。

| 変数 | 値 |
| --- | --- |
| `CWS_EXTENSION_ID` | `jglehalaegleehefcefnfmmbblgkomeh` |
| `CWS_PUBLISHER_ID` | ストアの publisher ID。開発者ダッシュボードで確認する |
| `GCP_SERVICE_ACCOUNT` | ストアに登録したサービスアカウントのメールアドレス |
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | `projects/番号/locations/global/workloadIdentityPools/名前/providers/名前` |

Environment の作成だけでは Google への認証は有効になりません。未設定の変数がある場合は、認証やアップロードの前に停止します。

## Google 側の初期設定

[サービスアカウントの公式手順](https://developer.chrome.com/docs/webstore/service-accounts) と [GitHub との認証連携](https://github.com/google-github-actions/auth#workload-identity-federation-through-a-service-account) に従って設定します。

1. Google Cloud のプロジェクトを選択し、Chrome Web Store API、IAM、Service Account Credentials、Security Token Service の必要な API を有効にします。
2. 提出用のサービスアカウントを作り、そのメールアドレスを Chrome ウェブストア開発者ダッシュボードのパブリッシャー設定に登録します。
3. GitHub から Google Cloud へ認証するための Workload Identity Pool と OIDC Provider を作成します。issuer は `https://token.actions.githubusercontent.com` です。属性マッピングに `google.subject=assertion.sub`、`attribute.repository_id=assertion.repository_id`、`attribute.repository_owner_id=assertion.repository_owner_id` を指定します。
4. Provider の属性条件を次に限定します。

   ```text
   assertion.repository_id == '1318975093' && assertion.repository_owner_id == '235082076' && assertion.sub == 'repo:apricot-cake@235082076/sift@1318975093:environment:chrome-web-store'
   ```

5. この Environment の subject に、対象サービスアカウントの `roles/iam.workloadIdentityUser` を付与します。principal は次の形式です。プロジェクト番号と Pool 名を設定した値に置き換えます。

   ```text
   principal://iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/POOL_NAME/subject/repo:apricot-cake@235082076/sift@1318975093:environment:chrome-web-store
   ```

6. 前節の Environment variables を設定します。Google 側の設定が反映されてから接続を確認します。

ワークフローは Google 公式の認証 Action で、`chromewebstore` scope の有効期間の短いアクセストークンを取得します。サービスアカウントの秘密鍵を作成・保存する必要はありません。

WXT 同梱の提出 CLI はサービスアカウントの秘密鍵を使う構成のため、このフローでは使いません。認証は公式 Action に任せ、既存アイテムの状態確認・アップロード・審査提出だけを公式 API v2 へ送ります。[API の対応範囲](https://developer.chrome.com/docs/webstore/api/reference/rest)
