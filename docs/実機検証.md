# 実機検証

Sift の対応ページで、パネルの起動・フィルター・ページ遷移を確認する手順。検証を依頼するときは「実機検証手順に沿ってスモークテストして」でこの文書を参照できる。

## 準備

1. `npm run typecheck` と `npm test` を実行する。必要に応じて `npm run lint` も確認し、実機の結果とは分けて記録する。
2. 拡張機能を変更した場合は `npm run build:candidate` で候補を作り、`npm run browser:candidate` で開発用Chromeに読み込む。ビルドIDと成果物ハッシュを記録する。日常版へ配備するのは検証後とする。
3. `npm run browser:open` で開発用Chromeを起動し、`npm run browser:status` で接続先を確認する。普段用Chromeは使わない。
4. `chrome.storage.sync` の `settings` を読み取り、ローカルの `test-results/` などへ退避する。Cookie・認証情報は取得・記録しない。終了後に設定を戻すための記録として使う。
5. 対象ページを開く。既存のタブを再利用する。各サイトの再利用可能なタブは残し、用済みのテスト用タブだけ閉じる。

サイト上の投稿・いいね・フォロー・リポスト・リスト編集などは行わない。読み込み済みの実投稿だけを使い、ダミー投稿や検証用DOMは注入しない。無制限のスクロールや巡回はしない。

## マトリクス

フィルター同士の組み合わせは行わない。他のフィルターを無効にし、各項目を「適用→解除」で1ケースとする。プルダウンの全候補は網羅せず、表示・非表示の両方が生じる代表値を選ぶ。

| サイト | ページ | 並び順 | 単体で確認する項目 | 状態数 | ケース数 |
| --- | --- | --- | --- | ---: | ---: |
| YouTube | チャンネルの動画・配信 | 新しい順 | 最低再生回数、新しい動画を除外、メンバー限定を除外 | 2 | 6 |
| YouTube | 同上 | 人気の動画 | 投稿期間、メンバー限定を除外 | 2 | 4 |
| YouTube | チャンネルのショート | 新しい順・人気の動画 | 最低再生回数、メンバー限定を除外 | 2 | 4 |
| ニコニコ動画 | ユーザーの投稿動画一覧 | 投稿日時が新しい順・再生数が多い順 | 最低再生回数、新しい動画を除外 | 2 | 4 |
| X | フォロー中、ホーム内固定リスト、リスト専用ページ、検索、プロフィールのポスト | 検索は最新のみ。他はサイトの通常表示 | 最低いいね数、コンテンツタイプ、返信・引用投稿・リポストを除外 | 5 | 25 |
| Bluesky | フォロー中、ホーム内固定リスト、リスト専用ページ、検索、プロフィールの投稿・メディア・ビデオ | 検索は最新のみ。他はサイトの通常表示 | 最低いいね数、コンテンツタイプ、返信・引用投稿・リポストを除外 | 7 | 35 |
| 合計 | | | | 20 | 78 |

20状態・78ケースは上限。サイトに存在しないタブや並び順は対象なし（N/A）とし、合格には数えない。現行の対象範囲は [対応サービス](対応サービス.md) と照合する。ショートは一覧に投稿日がないため、どちらの並び順も最低再生回数で絞り込む。ニコニコの再生数が多い順も現状は最低再生回数と新しい動画の除外であり、YouTubeの投稿期間UIとは異なる。

YouTubeの並び順判定を変更した場合は、タブ・チップ型とプルダウン型の両方を確認する。各表示形式で新しい順・人気の動画の操作欄と、古い順の対象外表示を確認する。プルダウン型の確認例は `https://www.youtube.com/@sutehage_channel/videos`。表示形式はサイト側で変わるため、検証時に実際の要素を確認して結果に記録する。

## パネルの開閉

各ページ・並び順で閉じた状態から起動する。開いたパネルの使い回しだけでは起動の合格にしない。

```sh
npm run smoke:panel -- "https://www.youtube.com/@Google/shorts"
```

このコマンドは指定URLと完全一致する既存タブを1つだけ対象にする。URL遷移やフィルター単体テストは実行しない。実行中はウィンドウのサイズやタブを手動で変更しない。

1. CDPの `Extensions.triggerAction` で準備起動する。これは再起動後の `activeTab` 権限を取得するためで、初回起動の合格には数えない。
2. 拡張機能のバックグラウンドに一時的な `sidePanel.onOpened` / `onClosed` の観測を登録する。サイトのDOMは変更しない。
3. パネルを閉じ、通知履歴をクリアし、ページの表示幅を記録する。
4. 拡張アクションを呼び出し、対象のタブID・ウィンドウID・パスに一致する `onOpened` を待つ。パスは `sidepanel.html` と `/sidepanel.html` を同一と扱う。
5. ページ幅の縮小、パネルの `visibilityState === "visible"`、表示寸法、接続先タブ、内容を確認する。
6. パネルを閉じ、同じ対象の `onClosed` とページ幅の復元を確認する。
7. 一時リスナーを解除し、CDP接続を閉じる。結果をJSONで標準出力へ出す。判定失敗時は終了コード1になる。

終了時はパネルを閉じる。準備起動を含め、Siftの通常動作によって最低値・投稿期間の選択は「指定なし」に戻る。設定を保存してから実行すること。失敗時はパネルが開いたままの可能性があるので、状態を確認して片付ける。

タブが複数ある、バックグラウンドが見つからない、通知が来ない、ページ幅が変わらないなどの場合は、推測で合格にせず環境と結果を記録する。幅の変化だけでも合格にしない。

この確認は実アイコンクリックではない。必要ならユーザーのクリックを別枠で記録する。CDPターゲットの存在・`getOptions().enabled`・パネル単体のキャプチャだけを、実表示の証拠にしない。開閉判定は見た目の崩れまで保証しない。

## フィルター単体

以下の単体検証に加え、後述の「接続とアクセス権」の確認も毎回必須とする。

開閉確認の後にパネルを開き直し、対象タブと表示内容を確認してから開始する。

1. 最低値は「指定なし」、除外トグルはオフ、コンテンツタイプは制限なしにする。
2. DOMから実際のラベルと位置を読み、CDPの `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` / `Input.insertText` で操作する。設定ストレージの直接書き換えやDOMの `.click()` で操作テストを代用しない。
3. 対象フィルターを1つ適用する。UIの選択値に加え、実投稿の指標・日時・種類と表示結果を照合する。`data-sift-filter-state` と `data-sift-filter-reason` は補助情報であり、属性だけで期待値の正しさを証明しない。
4. 解除後に非表示状態が残らないことを確認する。
5. 件数が追加読み込みで変化した場合は、対象投稿と時点を記録して比較する。固定件数を前提にしない。連続読み込みが続く場合は条件を解除し、ケースを中断して記録する。

除外対象の投稿がない場合は「操作確認のみ」。フィルターの効果確認済みとはしない。欠損指標を持つ投稿は仕様上非表示にしない。

## 接続とアクセス権

毎回のスモークテストで実施する。78ケースとは別枠であり、通常の開閉テストでは代用しない。パネルを閉じても `activeTab` の権限は残るため、準備起動後の開閉だけでは未許可状態を確認できない。

```sh
npm run smoke:connection
```

開発用Chromeの既存Siftパネルを閉じてから実行する。Xのプロフィールを閲覧できるログイン状態が必要。検証用タブを2つ作り、次を確認する。

| 状態 | 合格条件 |
| --- | --- |
| Xプロフィールで拡張アクション実行 | 対象タブの最低いいね数などの操作欄が表示される |
| 同じタブをYouTubeへ別オリジン遷移。アクションは実行しない | 未接続とツールバー操作の案内が表示され、対象外表示・古い操作欄が残らない |
| YouTubeで拡張アクション実行 | 同じタブに再接続し、最低再生回数などの操作欄が表示される |
| YouTubeを再読み込み | 操作欄が復旧する |
| 別のXプロフィールタブで拡張アクション実行 | 接続先が新しいタブになり、最低いいね数の操作欄が表示される |
| 元のYouTubeタブへ戻る | 接続先と操作欄がYouTubeに戻る |

各段階で可視状態・表示寸法・アクティブタブID・サイト別の内容を照合する。セッションストレージのタブIDは最後の起動先であり、現在の接続先の証拠には使わない。期待状態が連続して確認できなければ失敗とする。ログイン画面・読み込み失敗・権限が常時付与された環境などで前提を再現できない場合も、合格として扱わない。

結果は `test-results/connection-smoke.json` に保存し、失敗時は終了コード1になる。作成したタブだけを閉じ、退避した設定を復元する。設定の退避先は `test-results/connection-settings-before.json`。強制終了した場合はこの退避データを使って復元し、テストタブを片付ける。ビルドIDは準備時の記録と併せて残す。

この検証はCDP経由の接続状態テストであり、実際のツールバークリック固有の問題や全ページのフィルター動作を保証しない。

## 対象外と遷移

以下は78ケースとは別枠。対象外でもアイコンから案内パネルが開き、フィルター操作欄が出ず、ページ上に非表示状態が残らないことを確認する。

| サイト | 対象外の代表例 |
| --- | --- |
| YouTube | チャンネルホーム、古い順、検索、登録チャンネル、チャンネル内検索、視聴ページ |
| ニコニコ動画 | 古い順、再生数が少ない順、コメント順など他の並び順、検索、タグ、マイリスト |
| X | おすすめ、検索の最新以外、個別投稿、プロフィールのポスト以外のタブ |
| Bluesky | カスタムフィード、検索の最新以外、個別投稿、プロフィールの返信 |
| 対象外サイト | example.comなど。サイトへの処理注入がないことは背景処理のテストと併せて確認 |

パネルを開いたまま、対応→対象外→対応、並び順変更、タブ切り替え、再読込を確認する。閉じて再表示した際の「指定なし」初期化も確認する。拡張機能更新を挟むケースはビルドを分けて記録する。

## 結果と終了処理

結果は `test-results/` に保存する（Git管理外）。日時、ビルドID、Chromeバージョン、ページ、並び順、操作方法、条件、期待値、実測、判定、未確認理由を記録する。次の形式を使える。

| ページ・並び順 | 起動方法と結果 | フィルター | 条件 | 期待値・実測 | 判定・理由 |
| --- | --- | --- | --- | --- | --- |
| | CDPアクション／実クリック | | | | 合格／不合格／操作確認のみ／N/A／未実施 |

起動状態数とフィルターケース数を別々に集計する。途中結果や古いビルドの結果を全件完了として扱わない。修正を挟んだ場合はビルドIDを更新し、影響ケースを再検証する。

終了時は変更した設定を元に戻し、一時リスナー・CDP接続を解放する。用済みのテストタブは閉じ、再利用するタブは残す。失敗ケースを発見しても、検証依頼だけなら実装を勝手に変更せず報告する。

配備の全検証は `npm run verify:candidate` で実行する。一部ケースだけの実行や基準更新時の結果は配備の合格記録にしない。全検証後、main の主作業ツリーで `npm run deploy:local` を実行すると、ソースと成果物のハッシュを再確認して同一成果物を配備する。詳しくは [互換性検証の設計](互換性検証の設計.md) を参照する。
